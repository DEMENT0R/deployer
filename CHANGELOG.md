# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).
Версий и тегов у проекта пока нет, поэтому разделы датированы по коммитам.

## 2026-07-28

### Добавлено

- **URL инстанса и health-пинг.** У инстанса появилось необязательное поле `url` (`http`/`https`, задаёт
  админ). В списке инстансов и в шапке страницы — ссылка на стенд; на странице инстанса — бейдж
  `Up` / HTTP-код / `Unreachable` со временем ответа. Пинг ходит на `GET /instances/{instance}/health`
  (`InstanceHealthService`, throttle 30/мин, политика доступа та же, что и у инстанса) при открытии
  страницы, после завершения деплоя и по кнопке ↻. Таймаут — `DEPLOYER_HEALTH_TIMEOUT` (5с).
- **Блок Working tree на странице инстанса** (`InstanceStatusService`): текущая ветка или `detached HEAD`,
  HEAD-коммит (short sha, тема, автор, дата), `ahead`/`behind` относительно `<remote>/<branch>`, число
  незакоммиченных файлов и счётчик stash'ей. Считается локальными git-командами без обращения к сети,
  поэтому `ahead`/`behind` свежи настолько, насколько свеж последний `fetch`. Отдаётся через
  `Inertia::defer`: не задерживает первую отрисовку и не участвует в 3-секундном поллинге деплоя,
  а обновляется сам после завершения деплоя.
- **История деплоев** — последние 20 по инстансу: время, действие, ветка, кто запустил, длительность,
  статус и код выхода. Логи в таблицу не тянутся.
- `GitService`: `headCommit()`, `divergence()`, `stashCount()`, публичный `statusLines()`.

### Изменено

- История деплоев сортируется по `created_at desc, id desc` — по одному `created_at` деплои,
  запущенные в одну секунду, шли вразнобой.
- Карточка в списке инстансов больше не одна сплошная ссылка: имя ведёт на страницу инстанса,
  адрес стенда — на сам стенд.

## 2026-07-27

### Добавлено

- **Просмотр `.env` целевого проекта** в админке (`Admin → Instances → Env`, `InstanceEnvService`):
  путь, размер, дата изменения и таблица переменных. Наружу уходят только ключи из
  `deployer.env_visible_keys`, значения по `deployer.env_masked_patterns` маскируются на сервере,
  остальные переменные отдаются числом — без имён и значений. Только чтение, только админ.
  Размер парсимого файла ограничен `DEPLOYER_ENV_MAX_SIZE` (256 КБ).
- **Автоматический stash** перед `git checkout`: грязное рабочее дерево целевого проекта больше не валит
  деплой. Untracked включаются, ignored (`.env`, `vendor`, `node_modules`) — нет. Выключается через
  `DEPLOYER_AUTO_STASH=false`.

### Исправлено

- Экран «419 Page Expired» на вкладке, пережившей `SESSION_LIFETIME`: Inertia перезагружает страницу
  за свежим CSRF-токеном, а при умершей сессии уводит на логин.

## 2026-07-23

### Добавлено

- Первая рабочая версия: реестр инстансов, выбор ветки из git-remote с кэшем, четыре действия деплоя
  (полный / только ветка / миграции / фронтенд) пошаговой джобой, живой прогресс и лог поллингом,
  роли admin/tester, админский монитор очередей, валидация путей (`PathValidator`) и имён веток.
- Рейт-лимит 10 запросов деплоя в минуту на пользователя и запрет параллельных деплоев на один инстанс
  (проверка в БД + кэш-лок).

### Изменено

- Вывод команд копится в буфере и пишется в `deployments.output` по размеру/времени, а не на каждый чанк.
- Подпроцессам git явно передаются `SystemRoot`, `PATH` и прочие переменные окружения: под веб-SAPI
  на Windows их потеря роняла git с `getaddrinfo() thread failed to start`.
